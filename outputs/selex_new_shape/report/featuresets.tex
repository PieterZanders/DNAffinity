\subsection{Shape feature sets benchmarked}\label{sec:fs}
Three shape feature sets from \texttt{data/selex} were compared. Everything else was identical: labels from \texttt{4.txt} (the shape files have none), log affinity, count $\geq$10, per-strand rows, \texttt{avg}+\texttt{fce}, one-hot, per-fold standardisation, and the same test split and grouped folds. Per window, \texttt{avg} has 6 values and \texttt{fce} 21.

In the per-position layout, hexamer $s[j{:}j{+}6]$ ($j=0..4$) is placed at tetramer position $j{+}1$, its central tetramer. The two end positions get zero hexamer channels, which become constant values after standardisation (\texttt{lib.windowed}). Flat models concatenate the 5 hexamer windows without padding (\texttt{lib.flat\_feats}). The tetramer runs (a) are the final runs of Section~\ref{sec:models}.

\subsection{Timing}
All timings were measured on the box: 8-core Intel Xeon CPU (1 thread per core), 15\,GB RAM, no GPU, PyTorch on CPU.
\begin{itemize}
\item Jobs ran as 8 parallel workers. NNs, Linear, Ridge and SVR used 1 thread each; RF used 6 threads (\texttt{n\_jobs}=6) and LightGBM 4. Workers competed for cores, so times are indicative and comparable within this benchmark.
\item \emph{Feature time} is building the feature matrix for all 13{,}100 rows.
\item \emph{Training time} per run is the wall time of \texttt{fit} (including early stopping) plus one prediction pass over all rows.
\item \emph{Inference} is a separate \texttt{predict} on the 1{,}335 test rows, scaled to 1{,}000 sequences.
\item The original tetramer runs did not log timing. They were re-timed by rerunning the same code with seed 0 for every fold (5 runs per model) under the same parallel setup. Their reported total is the per-run mean times the number of runs.
\end{itemize}
